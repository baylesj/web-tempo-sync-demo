Web Tempo Sync is a proposed web API that lets a page play in time with music apps and hardware on the local network, and with other pages: shared tempo, bar phase and start/stop, with nothing to install. The tools under play share one session: start one, switch to another, and they stay in time with each other and with Ableton Live.

02get the api

No browser ships Web Tempo Sync yet. Three ways to try it:

  • The extension, on stable Chrome (macOS): an extension and a small helper app that join Link sessions. Download it (0.6 MB), then follow the install steps.
  • The prototype Chromium (macOS, Apple silicon): the API built into the browser. See setup.
  • The stand-in, in any browser: without the API, this page uses a stand-in that syncs only this browser's tabs. The status line says which one you're using.

01two tabs

In any browser, the stand-in syncs this browser's tabs with each other over a BroadcastChannel. No custom browser build is needed.

  1. Click Connect. The status line shows stand-in.
  2. Click New window, and Connect there too. Both show that they're playing along.
  3. Pick different patterns in the sampler in each window and press Play or the space bar.
  4. Start and stop wait for the next bar line, and the tempo slider moves both windows at once.

02stable chrome

The Web Tempo Sync extension gives stable Chrome navigator.tempoSync, using a small helper app that joins Link sessions.

Download extension 0.2.0 macOS, Apple silicon and Intel · 0.6 MB · sha256

Unzip it, then run these in Terminal from the unzipped folder. The helper isn't signed, so xattr -cr clears macOS's quarantine flag first. The script registers the helper with Chrome, so leave the folder where it is. 

xattr -cr .
extension/install-host.sh
  1. Open chrome://extensions, turn on Developer mode, choose Load unpacked, and pick the extension folder inside it.
  2. Reload this page and click Connect, then Allow. The status line shows extension.
  3. To remove it: extension/install-host.sh --uninstall, then remove the extension in chrome://extensions.

03ableton live

In the prototype Chromium build, the browser itself joins Link sessions and syncs with Ableton Live on the same laptop or local network.

Download Chromium v0.2.0 macOS, Apple silicon · 228 MB · sha256

The build isn't signed with an Apple developer ID, so macOS says it can't be trusted when it comes from a browser download. Downloading it in Terminal avoids that: curl doesn't mark files as downloaded from the internet, so there's nothing to clear. 

curl -O https://bayl.es/tempo-sync-demo-builds/v0.2.0/Chromium-tempo-sync-v0.2.0-macos-arm64.zip
ditto -x -k Chromium-tempo-sync-v0.2.0-macos-arm64.zip .
./Chromium.app/Contents/MacOS/Chromium \
  --enable-blink-features=TempoSync \
  "https://bayl.es/tempo-sync/?autoconnect=1"

Downloaded with the button instead? Clear the quarantine flag first, from the folder you unzipped it in: xattr -cr Chromium.app. Without it, macOS won't open it.

The earlier v0.1.0 implements an older draft of the API; this page adapts it, and the status line shows browser v0.1.

  1. In Ableton Live 12, open Settings > Link, Tempo & MIDI and enable Show Link Toggle and Start/Stop Sync.
  2. Click the Link button in the top-left corner of Live.
  3. The status line here shows that you're playing along.

04ableton move

You do not need a Wi-Fi router to sync with an Ableton Move on the road. In Standalone Mode, Move exposes a USB-C network interface (http://move.local) that carries Ableton Link traffic over a single USB-C cable.

  1. On Ableton Move, press Shift + Step 2 (Setup), set Mode: Standalone (not Control Live), and turn Link: On and Sync Start/Stop: On.
  2. Plug Move's USB-C port (next to the power port, not the USB-A port) directly into your Mac.
  3. Start the browser after plugging Move in, so it finds the USB network interface alongside en0 and lo0.
  4. The browser, Ableton Live and Ableton Move discover each other and lock tempo, beat phase and start/stop over USB.

05wi-fi & latency

  • Shared Wi-Fi or phone hotspot: Connect devices to a local network or hotspot that allows peer-to-peer UDP multicast (client isolation off).
  • Turn off corporate VPNs: VPN tunnels often intercept or drop multicast packets.
  • macOS local network permission: The first time the browser joins, macOS may ask to let it find devices on your local network. Allow it, or it sees no one.
  • Measure audio output offset: Turn on measure output latency in the sampler and record this browser's output alongside Live's metronome in a DAW.

01audio clock

Passing an AudioContext to session.captureState(audioContext) puts the snapshot's times in AudioContext.currentTime, at the time the audio leaves the speakers: 

const audioContext = new AudioContext();
const session = await navigator.tempoSync.requestSession({ quantum: 4 });

let nextStep = null; // the next 16th-note step, in beats, not yet scheduled

// Runs every 25 ms. Each call schedules only the steps it hasn't scheduled before, so a step
// that falls inside several overlapping lookahead windows still plays once.
function scheduleLookahead() {
  const state = session.captureState(audioContext);
  const now = audioContext.currentTime;
  const horizon = now + 0.100; // 100 ms lookahead window

  if (nextStep === null) {
    nextStep = Math.ceil(state.beatAtTime(now) * 4) / 4;
  }
  for (; state.timeAtBeat(nextStep) < horizon; nextStep += 0.25) {
    triggerStepAtTime(nextStep, state.timeAtBeat(nextStep));
  }
}

setInterval(scheduleLookahead, 25);

02transport & ui

Participants share bar phase, not beat numbers. requestBeatAtTime() starts this page's beat 0 on the next bar line without moving anyone else's. With no context, captureState() uses performance.now() / 1000, for visuals: 

// Start a loop on the next bar line, and the transport with it.
function startOnNextBar() {
  const state = session.captureState(audioContext);
  state.requestBeatAtTime(0, audioContext.currentTime);
  if (!state.isPlaying) {
    state.setIsPlaying(true, state.timeAtBeat(0));
  }
  session.commitState(state);
}

// 60 fps phase ring
function renderLoop() {
  const state = session.captureState();
  drawBeatRing(state.phaseAtTime(performance.now() / 1000), state.tempo, state.isPlaying);
  requestAnimationFrame(renderLoop);
}

// "Playing along with Live", or not
session.addEventListener("peerschange", () => showStatus(session.hasPeers));

03webidl

The browser owns the network and the clock synchronization. Pages see only the timeline, and one bit about everyone else: whether anyone is playing along. 

[SecureContext]
partial interface Navigator {
  readonly attribute TempoSync tempoSync;
};

[SecureContext, Exposed=Window]
interface TempoSync {
  Promise<TempoSession> requestSession(optional TempoSessionOptions options = {});
};

dictionary TempoSessionOptions {
  double quantum = 4;
};

[SecureContext, Exposed=Window]
interface TempoSession : EventTarget {
  readonly attribute boolean hasPeers;
  readonly attribute double quantum;
  TempoSessionState captureState(optional BaseAudioContext context);
  undefined commitState(TempoSessionState state);
  undefined close();
  attribute EventHandler onpeerschange;
  attribute EventHandler ontimelinechange;
  attribute EventHandler onplayingchange;
};

[SecureContext, Exposed=(Window,Worker,AudioWorklet), Serializable]
interface TempoSessionState {
  readonly attribute double tempo;
  undefined setTempo(double bpm, double atTime);
  double beatAtTime(double time, optional double quantum);
  double phaseAtTime(double time, optional double quantum);
  double timeAtBeat(double beat, optional double quantum);
  undefined requestBeatAtTime(double beat, double time, optional double quantum);
  undefined forceBeatAtTime(double beat, double time, optional double quantum);
  readonly attribute boolean isPlaying;
  readonly attribute double timeForIsPlaying;
  undefined setIsPlaying(boolean playing, double atTime);
};
